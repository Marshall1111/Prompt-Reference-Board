# 冰箱贴收款上线清单

当前项目使用**商户收款码 + 人工确认到账**，不调用微信支付 JSAPI、H5 或 Native 接口。

## 用户付款流程

1. 用户提交冰箱贴订单；订单为“待确认收款”。
2. 网站和小程序显示商户收款码、应付金额、订单号和付款截止时间。
3. 用户用微信扫码，并按订单金额付款；应在转账备注中填写订单号。
4. 管理员在商户收款记录中核对金额和订单号后，在后台订单详情点击“确认已收款”。
5. 系统将订单转为“待发货”，并只在首次确认时赠送每枚 10 点、永久解锁该账户的原图下载。

收款码静态文件位于 `public/payment/wechat-merchant-collection.png`；小程序使用同一份图像的副本 `wechat-miniprogram/miniprogram/images/wechat-merchant-collection.png`。

## 管理员操作

在网站管理后台的“订单管理”中：

1. 按订单号、金额和微信商户收款记录核验到账；不要仅凭用户截图确认。
2. 打开订单详情，点击“确认已收款”。
3. 订单会进入“待发货”，再填写快递公司、运单号，并标记“已发货”。

“确认已收款”是幂等的：重复点击不会重复赠点或重复解锁。不要直接通过数据库修改订单状态。

## 不需要配置的微信参数

当前模式不需要配置公众号 AppID、AppSecret、商户 API 证书、APIv3 密钥、支付通知 URL，也不需要申请 H5、Native 或 JSAPI 支付产品。项目保留了将来重新接入微信支付接口的代码，但当前下单不会调用它。

## 商品与点数规则

- 单价与邮费可在后台“订单管理 → 下单配置”调整；当前规则为 1 枚收邮费，2 枚及以上包邮。
- 每笔已确认收款的实体订单：每枚赠送 10 点，并永久解锁该账户卡夹中的全部原图下载。
- 用户付款后直到管理员确认前，订单始终是待付款/待确认状态，不会自动发货或赠点。
