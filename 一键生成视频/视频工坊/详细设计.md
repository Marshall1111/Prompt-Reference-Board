# 小画视频工坊（视频生成 EXE）详细设计文档

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 对应代码 | `一键生成视频/视频工坊/` 下 `main.py`、`petpaint_api.py`、`qr_page.py`、`video.py`、`config_store.py`、`build.ps1` |
| 产物 | `一键生成视频/视频工坊/dist/小画视频工坊.exe`（约 269.9 MB，单文件、无控制台） |
| 依赖服务 | petpaint 管理端接口（`/api/admin/*`、`/api/styles`、`/api/image-jobs`） |
| 前置 | 后台已存在成功任务；有一个 BGM 音频文件；Windows 10/11 |

---

## 1. 概述

### 1.1 工具定位

小画视频工坊是**运营人员使用的卡点视频生产工具**。它从 petpaint 服务器读取历史 AI 转绘任务，按关键词/风格筛选，人工挑 6 个任务，用每个任务的「原图 + 转绘图」自动生成一条竖屏卡点对比视频：

```
原图1（推近）→ 转绘1（静止）→ 原图2（推近）→ 转绘2（静止）→ … ×6 → 结尾页（二维码）
```

结尾页是可编辑的黑底二维码页：上方文案默认「AI小画家，让照片更有趣」，下方默认「扫码做同款」，二维码指向带商户邀请码与风格 ID 的落地页。

工具把原来「手工收集素材 → 剪映对齐鼓点 → 导出 → 做二维码结尾页」的流程压缩成三步点选。

### 1.2 设计目标

| 目标 | 实现方式 |
|---|---|
| 不依赖手工找图 | 直接查后台成功任务，缩略图并在界面预览 |
| 选材直观 | 点击行即预览并选中，最多 6 个、可排序 |
| 输出参数可调 | 帧数、结尾时长、推近幅度、分辨率在界面可改 |
| 二维码可控 | 网址、店家邀请码、风格 ID、上下文案均可编辑，实时预览 |
| 卡点准确 | 自动检测 BGM 起点 + 每张固定帧数（默认 24 帧 @30fps ≈ 75 BPM） |
| 可分发维护 | 打包单文件 EXE，源码与 EXE 入库（EXE 走 Git LFS） |

### 1.3 非目标

- 不做视频剪辑时间线编辑（没有多轨、转场、字幕动画）。
- 不做批量出片（一次一条，选 6 个任务）。
- 不替代后台的任务创建/风格管理。
- 不保存管理员密码。

## 3. 总体架构

### 3.1 分层

| 层 | 文件 | 职责 |
|---|---|---|
| 界面层 | `main.py` | 三步向导、列表/预览、选择管理、进度日志 |
| 接口层 | `petpaint_api.py` | 登录保持、任务查询、图片下载、店家列表 |
| 素材层 | `qr_page.py` | 拼落地 URL、生成结尾页 PNG |
| 渲染层 | `video.py` | 帧序列生成、音轨处理、调用 ffmpeg 编码 |
| 配置层 | `config_store.py` | `%APPDATA%\PetpaintVideoMaker\config.json` 读写 |

### 3.2 线程与消息模型

```
tkinter 主线程
   │ 点击
   ├─▶ 网络线程：登录 / 查询 / 缩略图(8 并发) / 预览(2 并发)
   ├─▶ 生成线程：下载 6 组素材 → 结尾页 → render_video
   │
   ├─ 回调统一 self._post(cb) = self.after(0, cb)
   └─ 日志统一 log_queue.put() → 主线程每 200ms 轮询消费
```

- `self.busy` 作为全局互斥：登录、查询、生成期间禁止重复触发。
- 生成期间禁用「开始生成」，关闭窗口会二次确认。
- 所有工作线程 `daemon=True`。

## 4. 界面设计

### 4.1 页签一：① 选择历史任务

**服务器与登录区**

- 服务器（默认 `https://www.petpaint.top`）、管理员账号、密码（掩码）、登录按钮、状态文本。
- 登录成功保存 `server` 与 `username`，**不保存密码**。
- 登录后并行触发：填充风格下拉、加载第 1 页任务、拉取店家列表。

**筛选区**

- 关键词输入框（回车查询）、风格下拉（「全部风格」+ `标题（ID）`）。
- 上一页/下一页、页码标签「第 x / y 页 · 共 n 条」。
- 查询固定附带 `status=succeeded`，只展示成功任务。

**任务表**

| 列 | 说明 |
|---|---|
| `#0` 缩略图 | 转绘图缩略图 64×64 |
| 序号 | 被选中的顺序（1–6），未选中为空 |
| 风格 | `styleName`，缺失回退 `styleId` |
| 任务号 | `jobId` |
| 完成时间 | `completedAt` 优先，`createdAt` 兜底，`T` 换空格截 19 位 |
| 参考图 | 参考图张数 |

过滤规则：没有参考图，或 `result` 中既无 `thumbnailUrl`、`imageUrl`、`previewUrl` 的任务不进入列表。

**预览区**

- 左「原图」、右「转绘图」，初始占位「—」。
- 下方信息：风格、任务号、完成时间、参考图张数与「取第 N 张」提示、提示词（截断 600 字）。

**已选区**

- 标题实时显示「已选任务（x/6）」。
- 列表按选择顺序展示「序号. 风格 · 任务号」。
- 上移、下移、移除、清空。

**交互约定**

- 单击表格行 = 展示预览 + 切换选中（再点一次取消）。
- 选满 6 个后再点新任务，弹提示「最多选择 6 个任务」。

### 4.2 页签二：② 结尾页二维码

| 控件 | 默认 | 说明 |
|---|---|---|
| 落地网址 | 配置值或 `https://www.petpaint.top` | 拼 `sameStyleId`、`invite` |
| 小画店家 | （不使用） | 登录后可拉取；选中自动填邀请码 |
| 邀请码 | 空 | 可手工填写，店家接口不可用时的兜底 |
| 指定风格 | （不使用） | 与页签一同一份风格列表 |
| 二维码上方文案 | AI小画家，让照片更有趣 | 结尾页上半部分 |
| 二维码下方文案 | 扫码做同款 | 结尾页下半部分 |
| 最终链接 | 只读 | 实时展示拼装结果 |
| 结尾页预览 | 黑底 300×450 | 250ms 防抖刷新 |

任一输入变化都通过 `trace_add` 触发 250ms 防抖重绘，避免每敲一个字都重新编码二维码。

### 4.3 页签三：③ 生成视频

**输出与音频**

- 输出目录（默认 `app_dir()/输出`）。
- BGM 路径：默认按以下顺序查找
  1. `app_dir()/素材/bgm.m4a`
  2. 上一级 `素材/bgm.m4a`
  3. 打包资源 `_MEIPASS/assets/bgm.m4a`
- 可手动选择 `*.m4a *.mp3 *.wav *.aac`。

**视频参数**

| 参数 | 默认 | 约束 |
|---|---|---|
| 每张帧数 | 24 | ≥1，30fps 下 0.8s ≈ 75 BPM |
| 结尾页帧数 | 62 | ≥1（约 2.07s） |
| 推近幅度 | 0.04 | ≥0，0 关闭推近 |
| 宽 | 1080 | ≥2 |
| 高 | 1620 | ≥2 |

帧率固定 30fps，背景固定黑色。

**操作**

- 开始生成（需已登录 + 恰好 6 个任务 + BGM 存在）。
- 打开输出文件夹（生成成功后启用）。
- 状态文本 + 日志区（自动滚动）。

## 5. 接口设计（`petpaint_api.py`）

### 5.1 会话与基础行为

- `requests.Session()`，UA `PetpaintVideoMaker/1.0`，默认超时 30s。
- `trust_env = False`：**忽略系统代理**。部分代理把 HTTPS 代理写成 `https://127.0.0.1:xxxx`，旧版 urllib3 会抛 `check_hostname requires server_hostname`，且本站直连即可。
- 路径以 `http(s)://` 开头时原样请求，否则拼 `base_url`。
- 统一错误映射：
  - 网络异常 → `PetpaintError("连接服务器失败：...")`
  - 401 → 「登录已失效，请重新登录。」
  - 403 → 「当前账号没有权限执行该操作。」
  - ≥400 → 优先用响应 JSON 的 `message`，否则「请求失败（HTTP xxx）」

### 5.2 接口清单

| 方法 | 路径 | 参数 | 返回/用途 |
|---|---|---|---|
| POST | `/api/admin/login` | `{username, password}` | 建立管理员会话（Cookie 由 Session 自动保存） |
| GET | `/api/styles` | — | `[{id, title, ...}]`，填充风格下拉 |
| GET | `/api/image-jobs` | `status=succeeded`、`page`、`limit`（1–100）、`search`、`styleId` | `{jobs: [...], total}` |
| GET | `/api/admin/store-owner-invites` | — | `{storeOwners: [{accountId, storeName, wechatId, inviteCode}]}` |
| GET | `/api/admin/image-jobs/{jobId}/result` | — | 转绘图原始字节 |
| GET | `/api/admin/image-jobs/{jobId}/references/{index}` | index 从 0 开始 | 原图原始字节 |
| GET | 缩略图 URL | 绝对/相对均可 | 缩略图字节，短超时独立会话 |

### 5.3 任务对象（用到的字段）

```json
{
  "jobId": "job_xxx",
  "styleId": "style_xxx",
  "styleName": "复古大字报",
  "prompt": "...",
  "completedAt": "2026-11-22T10:00:00.000Z",
  "createdAt": "...",
  "originalReferences": [
    { "thumbnailUrl": "/uploads/.../ref-1.webp", "order": 1 },
    { "thumbnailUrl": "/uploads/.../ref-2.webp", "order": 2 }
  ],
  "result": {
    "thumbnailUrl": "/uploads/.../result-thumb.webp",
    "previewUrl": "...",
    "imageUrl": "..."
  }
}
```

**参考图选择规则（`_reference_index`）**：参考图多于 1 张时取第 2 张（索引 1），否则取第 1 张（索引 0）。列表展示与最终下载使用同一规则，保证预览与成片一致。

### 5.4 `fetch_thumbnail` 的独立会话

缩略图是公开静态文件，使用一次性 `Session`（同样 `trust_env=False`）和 8s 超时；失败返回空字节，不抛异常，避免单张图拖垮列表加载。

## 6. 关键流程

### 6.1 登录

```
do_login()
  → 校验 server/username/password
  → busy=True，禁用登录按钮
  → 线程：PetpaintClient(server).login() → list_styles()
  → 主线程 _login_ok：保存 server/username，填充风格下拉，
     记录日志，load_jobs(1)，load_store_owners()
  → 失败 _login_failed：状态标红、日志、弹窗
```

### 6.2 任务查询与缩略图

```
load_jobs(page)
  → 读取关键词与风格 ID
  → 线程 query_jobs(...)
  → _render_jobs：
       重算总页数、翻页按钮状态
       清空表格与缩略图引用
       逐条过滤（需 refs 且 result 有图）
       插入行，job_by_iid 建立 iid→job 映射
       对转绘缩略图：命中 image_cache 直接显示，否则收集待下载
  → _load_thumbnails：8 线程并发拉取，回主线程生成 PhotoImage 挂到行上
```

`image_cache` 为 `{url: bytes}`，上限 400 条，超限整体清空（简单策略，避免无界增长）。`thumb_refs` 持有 PhotoImage 引用，防止被 GC 回收导致图片空白。

### 6.3 预览

```
_show_preview(job)
  → 同步渲染文字信息
  → 原图/转绘先查缩略图缓存，命中立即显示
  → preview_token += 1 作为「最新请求」标记
  → 线程（2 并发）：
       原图：缩略图 → 失败则 download_reference(jobId, index)
       转绘：缩略图 → 失败则 download_result(jobId)
  → _apply_preview：token 不匹配则丢弃（快速连点不会显示旧图）
```

预览图最长边限制 180×220，`Image.LANCZOS` 缩放。

### 6.4 结尾页与二维码

`build_qr_url(site_url, style_id, invite_code)`：

1. 空值回退 `https://www.petpaint.top`；无协议补 `https://`；
2. 用 `urlsplit/parse_qsl` 保留原有查询参数；
3. 依次追加 `sameStyleId`、`invite`（顺序固定，便于后台解析与排查）；
4. `urlunsplit` 输出。

`render_end_page_image(url, top, bottom)` 绘制规则：

| 元素 | 规格 |
|---|---|
| 画布 | 1080×1620，纯黑 `#000000` |
| 二维码底板 | 700×700 白色圆角矩形，圆角 28，居中 |
| 二维码 | 白色底 + 深色模块 `(11,11,13)`，纠错等级 M，整数倍缩放至约 600px，无 border |
| 上方文案 | 64px，米色 `(245,239,224)`，最多 2 行，每行宽度 ≤900 |
| 下方文案 | 72px，同色，最多 2 行，宽度 ≤900 |
| 间距 | 底板与文字间距 80px；行高 = 字号 × 1.3 |
| 字体 | `msyhbd.ttc` → `msyh.ttc` → `simhei.ttf` → `simsun.ttc` → Pillow 默认 |

二维码模块用逐像素绘制（`box_size=1` 计算整数倍）而非 `qrcode` 自带图片导出，保证模块边缘锐利、无插值模糊。

`save_end_page()` 生成 PNG 到临时目录，供渲染层使用。

### 6.5 生成视频

```
start_generate()
  → 前置校验：登录、恰好 6 个、BGM 存在、参数为数字
  → 取当前 url / 上下文案 / 6 个任务的快照（避免生成中改动界面影响结果）
  → busy=True，禁用按钮

生成线程：
  1. mkdtemp(prefix="petpaint_video_")
  2. 逐个任务：
       before = download_reference(jobId, reference_index)
       after  = download_result(jobId)
       任一为空 → RuntimeError
       按 PIL 识别格式存为 01_原图.jpg / 01_转绘.webp …
  3. qr_page.save_end_page(结尾页.png)
  4. video.render_video(pairs, end_page, bgm, out_dir, ...)
  5. 成功 → 主线程启用「打开输出文件夹」、保存配置、弹窗并打开目录
  6. 失败 → 弹窗显示原因
  7. finally 删除临时目录
```

图片扩展名由 `Image.open(BytesIO).format` 推断：JPEG/PNG/WEBP/BMP，未知按 `.jpg`。

## 7. 渲染引擎设计（`video.py`）

### 7.1 参数与校验

| 参数 | 默认 | 处理 |
|---|---|---|
| `pairs` | — | 必须恰好 6 组，文件必须存在 |
| `end_page_path` | — | 必须存在 |
| `bgm_path` | — | 必须存在 |
| `frames_per` | 24 | `max(1, int)` |
| `end_frames` | 62 | `max(1, int)` |
| `zoom` | 0.04 | `max(0, float)`，0 表示关闭 |
| `width/height` | 1080/1620 | `max(2, int)` |
| `fps` | 30 | `max(1, int)` |
| `bg` | `(0,0,0)` | 画布底色 |

### 7.2 BGM 起点检测（`detect_audio_start`）

1. ffmpeg 取前 3 秒 → 单声道 22050Hz f32le；
2. 512 窗 / 128 跳，逐窗 RMS；
3. 对 `log(RMS)` 做正向差分得到起音强度；
4. 阈值取最大值 50%，找第一个局部极大；
5. 返回 `t - 0.03`（提前 30ms），失败或静音返回 0.04。

目的：让第一张图与 BGM 第一个鼓点同时出现。

### 7.3 BPM 估算（`estimate_bpm`）

1. 全曲单声道 22050Hz；
2. 1024 窗 / 256 跳计算 RMS，求起音包络并去均值；
3. 自相关，在 0.5–1.3 拍/秒区间取峰值 lag；
4. `BPM = 60 / (lag / eff_fps)`，失败返回 `None`。

与「每张帧数」换算的理想 BPM 为 `60 × fps / frames_per`（24 帧 @30fps = 75）。差值 >3 时日志提示可调整每张帧数，但不阻断生成。

### 7.4 帧生成

| 片段 | 帧数 | 处理 |
|---|---|---|
| 每组原图 | `frames_per` | 等比放入画布并居中；`scale = 1 + zoom × smoothstep(t)`，`t = k/(frames_per-1)`，`smoothstep = t²(3-2t)`，用 LANCZOS 放大 |
| 每组转绘 | `frames_per` | 等比居中，静止 |
| 结尾页 | `end_frames` | 等比居中，静止 |

`render()`：`fit_box()` 取 `min(cw/w, ch/h)` 等比缩放，`scale>1` 时以画布中心放大，超出画布部分自然裁切；画布黑底，图片不裁切、不变形。

每帧直接 `tobytes()` 成 RGB24 原始字节，按顺序写入 ffmpeg 的 stdin，避免落盘成百上千张 PNG。

总帧数 = `6 × frames_per × 2 + end_frames`；默认 24/62 时 = 350 帧 ≈ 11.67s。

### 7.5 音轨处理

```
ffmpeg -y -i bgm -vn
  -af "atrim=start=<起点>,asetpts=PTS-STARTPTS,apad=whole_dur=<总时长>"
  -ac 2 -ar 44100 -c:a pcm_s16le _audio_tmp.wav
```

- `atrim` 从检测到的鼓点开始；
- `apad=whole_dur` 把不足的音频补静音到视频总长。这一条解决了「BGM 只有 10.64s，而 `-shortest` 把 11.69s 的视频截断」的问题；
- 先落成 PCM WAV，再参与第二次编码，避免容器兼容问题。

### 7.6 编码参数

```
ffmpeg -y -f rawvideo -pixel_format rgb24 -video_size WxH -framerate 30 -i -
       -i _audio_tmp.wav
       -c:v libx264 -preset medium -crf 18
       -pix_fmt yuv420p -profile:v high -level 4.1
       -r 30 -g 60
       -c:a aac -b:a 192k -ar 44100
       -shortest -movflags +faststart 成片_YYYYMMDD_HHMMSS.mp4
```

- `yuv420p` 保证手机/微信兼容；
- `faststart` 把 moov 前置，便于网页/微信秒开；
- GOP 60（2 秒一个关键帧）；
- stderr 写 `_ffmpeg_log.txt`，失败时读取末 2000 字符抛给界面。

### 7.7 资源清理

- 无论成功失败都删除 `_audio_tmp.wav`；
- 成功删除 `_ffmpeg_log.txt`，失败保留供排查（位于输出目录）；
- 生成结束时删除整个临时素材目录。

## 8. 配置与持久化（`config_store.py`）

路径：`%APPDATA%\PetpaintVideoMaker\config.json`（不可用则 `~`）。

```json
{
  "server": "https://www.petpaint.top",
  "username": "",
  "site_url": "https://www.petpaint.top",
  "top_text": "AI小画家，让照片更有趣",
  "bottom_text": "扫码做同款",
  "output_dir": "",

  "page_size": 50

```

- `load_config()` 以默认值为底，逐键覆盖，损坏 JSON 静默回退默认值；
- `save_config(patch)` 只接受已知键、忽略 `None`；

- 触发保存的时机：登录成功（server/username）、生成成功（输出目录/BGM/网址/文案）、关闭窗口（网址/文案/输出目录）。

## 10. 安全设计

| 项 | 设计 |
|---|---|
| 管理员密码 | 只在内存与登录请求中出现，不写配置文件、不写日志 |
| 会话 | `requests.Session` 内存 Cookie，进程退出即失效 |
| 缩略图 | 公开静态资源，独立短超时会话 |
| 店家信息 | 只读接口仅返回 `storeName/wechatId/inviteCode`，不含手机号等敏感字段 |
| 系统代理 | 主动忽略，避免代理证书/主机名问题，也避免凭据经过未知代理 |
| 打包 | `--windowed` 无控制台；源码与二进制入库，便于审计 |

## 11. 性能设计

| 环节 | 设计 | 说明 |
|---|---|---|
| 列表缩略图 | 8 线程并发 + 内存缓存（≤400 条）+ 8s 超时 | 一页 50 条可在数秒内铺满 |
| 预览 | 先缩略图后原图、2 并发、token 防串图 | 点击响应快 |
| 二维码预览 | 250ms 防抖、300×450 缩放 | 输入不卡顿 |
| 素材下载 | 6 组串行下载（每组 2 个文件） | 避免瞬时并发过高 |
| 帧生成 | 纯内存 RGB 字节流式写入 ffmpeg | 不产生数百张中间图 |
| 编码 | `preset medium`、`crf 18`、GOP 60 | 画质与速度平衡 |
| 日志 | 队列 + 200ms 轮询 | 不阻塞工作线程 |

## 12. 构建与发布

### 12.1 打包（`build.ps1`）

脚本为**纯 ASCII**（PowerShell 5 以 ANSI 读取中文会乱码），目录名与 EXE 名用 Unicode 码点拼出：

- 素材目录：`0x7D20 0x6750` → `素材`
- 成品名：`0x5C0F 0x753B 0x89C6 0x9891 0x5DE5 0x574A` → `小画视频工坊`

流程：

1. 检查 `PyInstaller, PIL, numpy, imageio_ffmpeg, requests, qrcode`，缺则 `pip install -r requirements.txt`；
2. `PyInstaller --onefile --windowed --name PetpaintVideoMaker`
   - `--collect-all imageio_ffmpeg`（必须，否则运行时找不到 ffmpeg.exe）
   - `--collect-submodules qrcode`
   - hidden imports：`PIL._tkinter_finder`、`PIL.WebPImagePlugin`、`PIL._webp`、`PIL.JpegImagePlugin`、`PIL.PngImagePlugin`
   - `--add-data <素材/bgm.m4a>;assets`
3. 把 `dist/PetpaintVideoMaker.exe` 重命名为 `dist/小画视频工坊.exe`（重命名前若被占用则提示关闭）。

### 12.2 体积说明（约 270 MB）

单文件模式会把以下运行时全部解压到临时目录：

- Python 解释器 + tkinter/Tcl；
- numpy（Anaconda 环境常带 MKL/OpenBLAS，体积占比最大）；
- imageio-ffmpeg 自带的 ffmpeg 可执行文件；
- Pillow（含 WebP 解码）、qrcode、requests。

这是「拿到就能跑、不装依赖」的代价。

### 12.3 版本管理

该 EXE 超过 GitHub 普通 Git 单文件 100 MB 限制，使用 **Git LFS**：

`.gitattributes`：

```
一键生成视频/视频工坊/dist/*.exe filter=lfs diff=lfs merge=lfs -text
```

首次提交后仓库里是 pointer 文件（约 134 字节）：

```
version https://git-lfs.github.com/spec/v1
oid sha256:1e8c65fc95554e9c6907b02a35ac1380551317a2b07ab00751eb75d5fcf38585
size 282988542
```

另一台电脑拉到源码后需要：

```bash
git lfs install   # 只需一次
git pull
git lfs pull      # 若 clone/pull 没有自动取 LFS 对象
```

注意：LFS 免费额度为 1 GB 存储/月、1 GB 流量/月；每次重新打包都会产生新对象（约 270 MB），因此不要频繁重建提交。

### 12.4 交付目录

```
一键生成视频/视频工坊/dist/
├── 小画视频工坊.exe
└── 输出/
    └── 成片_20261122_162426.mp4
```

`app_dir()` 在打包后取 EXE 所在目录，因此默认输出目录、`素材/bgm.m4a` 都相对 EXE 定位；整个 `一键生成视频` 文件夹可整体移动。

## 13. 运维与排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 登录报 `check_hostname requires server_hostname` | 系统代理指向 `https://127.0.0.1:xxxx` | 已在代码中 `trust_env=False`；如仍出现，检查是否有旧 EXE |
| 缩略图空白 | 服务器缩略图为 WebP，旧 Pillow 不支持 | 确认打包了 `PIL._webp`（Pillow 9.5+） |
| 列表加载慢 | 网络或缩略图体积大 | 已 8 线程并发 + 缓存；可调 `page_size` |
| 成片比预期短 | BGM 短且用了 `-shortest` | 已用 `apad=whole_dur` 补静音；确认版本 |
| 结尾页不显示 | 结尾页文件缺失/路径错 | 查看日志与临时目录 |
| 卡点不准 | BPM 与每张帧数不匹配 | 看日志里的 BPM 提示，调整「每张帧数」 |
| 推近不明显 | `zoom` 太小 | 提高到 0.05–0.08 |
| 编码失败 | ffmpeg 参数/磁盘空间/文件占用 | 输出目录保留的 `_ffmpeg_log.txt` 末段 |
| 输出目录打不开 | 目录被删/权限 | 重新选择输出目录 |
| 店家列表为空 | 接口未部署或账号无权限 | 手动填写邀请码即可 |

`dist/输出/` 下的 `_ffmpeg_log.txt` 仅在失败时保留。

## 14. 已知限制与后续演进

**已知限制**

- 固定 6 组素材、固定 2:3 竖屏风格，不支持任意组数。
- 帧率固定 30fps，背景固定黑色。
- 一页最多 100 条任务（服务端 `limit` 上限），翻页查询。
- 缩略图缓存为「超 400 条整体清空」，非 LRU。
- 生成期间界面仍可切页签，但选择与参数已快照，改动不会影响本次输出。
- EXE 体积大，依赖 Git LFS 分发，免费额度有限。
- 二维码颜色/底板尺寸写死，未暴露到界面。

**可演进方向**

- 支持 4/8/10 组素材与 9:16、1:1 画布模板。
- 结尾页样式模板（字体、颜色、Logo）。
- 按 BPM 自动计算每张帧数。
- 批量出片（多组 6 任务排队）。
- 直接把成片上传回后台或生成分享链接。
- 缩略图改为 LRU + 磁盘缓存，减少重复下载。
