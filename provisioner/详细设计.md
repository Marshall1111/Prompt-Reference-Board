## 1. 概述

### 1.1 工具定位

PetpaintProvisioner 是**上门安装人员使用的现场配置工具**。它运行在 Windows 笔记本上，通过局域网 SSH 连接一台刚刷好系统、尚未配置的 arm64 盒子（斐讯 N1 / 树莓派 4B，Armbian 或 Debian 12），完成以下全部工作：

1. 自动发现同网段内开放 22 端口的盒子；
2. 登录盒子并读取硬件/系统信息；
3. 读取、新增、修改、删除盒子上的 WiFi 配置；
4. 上传离线包并静默执行 `provision.sh`；
5. 实时回显安装日志，并在完成后提供「重启盒子」「测试打印」按钮。

最终目标：**盒子插上电源、接上打印机、连一根网线，操作员在图形界面点几下，就能变成一台可接单的打印盒子**，全程不依赖盒子访问互联网，也不需要操作员敲 Linux 命令。

### 1.2 设计目标

| 目标 | 实现方式 |
|---|---|
| 现场零命令行 | tkinter 三步向导，所有命令由工具拼装 |
| 断网可安装 | 全部依赖打入离线包，apt 使用本地源 |
| 可重复执行 | `provision.sh` 每一步都先检测再执行 |
| WiFi 切换不中断安装 | `setsid nohup` 让脚本脱离 SSH 会话，日志落盘轮询 |
| 不泄露凭据 | 密码只驻留内存，设备 token 只写入盒子且权限 600 |
| 可多人维护 | 源码、EXE、离线包全部纳入 git |

### 1.3 非目标

- 不做盒子的系统刷写（烧录镜像由操作员用 balenaEtcher 等工具完成）。
- 不做设备库存/设备 ID 的创建（在后台「信息维护 - 打印设备」中创建后导出 CSV）。
- 不替代 `print-agent` 的日常打印逻辑，只负责部署与冒烟验证。

## 3. 总体架构

工具分为四层：

| 层 | 文件 | 职责 |
|---|---|---|
| 表现层 | `main.py`（`App(tk.Tk)`） | 界面、交互、线程调度、进度与日志展示 |
| 设备操作层 | `core.py`（`Box`） | SSH 连接、命令执行、SFTP 上传、WiFi 读写、启动/轮询配置脚本 |
| 传输层 | paramiko | 密码认证 SSH + pipelined SFTP |
| 盒子侧执行层 | `provision.sh` + nmcli/CUPS/systemd | 真正的系统配置 |

表现层不直接调用 paramiko，只调用 `Box` 的方法；`Box` 不感知 tkinter，所有耗时操作由界面层放进 `threading.Thread(daemon=True)`，再用 `self.after(0, callback)` 回到 UI 线程。

### 3.1 线程模型

```
UI 主线程 (tkinter mainloop)
   │  用户点击
   ├─▶ 工作线程 A：扫描（ThreadPoolExecutor 128）
   ├─▶ 工作线程 B：连接 + 读系统信息
   ├─▶ 工作线程 C：WiFi 读/写
   └─▶ 工作线程 D：上传 + 等待 provision.sh
                                   │
                                   └─ self.after(0, ...) ──▶ 回到 UI 更新控件
```

约束：tkinter 控件只在主线程修改；所有跨线程回调用 `self.after(0, ...)` 包装；工作线程全部 `daemon=True`，关闭窗口不被阻塞。

## 4. 模块设计

### 4.1 `main.py`

#### 4.1.1 模块级常量与辅助

| 名称 | 说明 |
|---|---|
| `APP_TITLE` | 「小画家盒子配置工具」 |
| `DEFAULT_SERVER` | `https://www.petpaint.top` |
| `DEFAULT_QUEUE` | `cp1500` |
| `NAME_CACHE` | `%APPDATA%\PetpaintProvisioner\names.json`，IP→主机名缓存 |
| `load_name_cache()/save_name_cache()` | 缓存读写，失败静默（缓存不是关键路径） |
| `app_dir()` | 打包后取 EXE 所在目录，源码运行取 `main.py` 目录 |
| `find_offline_package()` | 依次在 `app_dir()/offline`、`../print-agent/offline` 找 `petpaint-offline-*.tgz`，取文件名排序最后一个 |

#### 4.1.2 界面结构

`ttk.Notebook` 三个页签，对应现场作业顺序：

**① 连接设备**

- 顶部：本机网段展示、`扫描设备`、`停止`。
- 左侧：扫描结果 `Listbox`，每行 `IP / 主机名 / SSH Banner`，双击填入 IP。
- 右侧：IP、用户名（默认 `root`）、密码、`连接` 按钮、设备信息只读文本框。
- 连接成功后展示主机名、系统、架构、根分区、打印机识别结果；同时异步读取 WiFi 列表。
- 架构不是 `arm64` 时弹警告（离线包只支持 arm64）。

**② 配置 WiFi**

- `Treeview` 列：连接名、WiFi 名称、优先级、隐藏 SSID、状态（已连接/备用），按优先级降序。
- 表单：连接名（只读，选中行自动填入）、SSID、密码、优先级（1–999，默认 300）、隐藏 SSID。
- 操作：新增、保存修改、删除选中、重新读取。
- 设计约定：
  - **新增**始终以 `petpaint-<清洗后的 SSID>` 作为新连接名，避免误改已有连接；
  - **保存修改**必须先在列表选中一行，改的是该连接名对应的配置；
  - 删除前二次确认。
- 底部红色提示：现场请用网线连接，切换 WiFi 会导致 SSH 短暂断开。

**③ 选择设备并执行**

- 离线包路径（自动发现，可浏览替换）。
- 设备 CSV（浏览后解析，填充设备下拉框）。
- 设备 ID 下拉框 + token 摘要（`前 8 位…后 8 位`，缺失标红）。
- 服务器地址、CUPS 队列名、「跳过打印机」勾选框。
- 操作按钮：开始配置、重启盒子、测试打印；右侧进度条。
- 日志区 `ScrolledText`，只读，自动滚到底部。

#### 4.1.3 关键方法

| 方法 | 作用 |
|---|---|
| `on_scan()` | 取本机 IP → `/24` 前缀 → 开线程扫描；期间禁用扫描、启用停止 |
| `_add_device()` | 扫描命中回调，写列表与 `self.scanned`，命中缓存名称 |
| `on_pick_device()` | 双击列表把 IP 填进登录表单并聚焦密码框 |
| `on_connect()` | 开线程 `box.connect()` → `system_info()` → `printer_present()` |
| `_connect_ok()` | 保存 `self.box`、展示信息、回填主机名、触发 WiFi 读取 |
| `_load_wifi_async()` | 线程读 `box.list_wifi()` 后 `_apply_wifi_rows` |
| `_run_wifi_action()` | 统一封装 WiFi 增删改：禁用按钮 → 线程执行 → 成功刷新/失败弹窗 |
| `on_pick_csv()` | `utf-8-sig` 读取 CSV，按 `deviceId` 建索引，下拉显示 `deviceId label` |
| `on_start()` | 校验连接/离线包/设备/至少一条 WiFi/二次确认，然后开线程执行 |
| `_finish()` | 成功则启用重启与测试打印并提示后台确认在线；失败提示查看日志最后 20 行 |
| `on_reboot()` | 确认后 `box.reboot()` |
| `on_test_print()` | 确认消耗 1 张相纸后线程调用 `box.test_print(queue)` |

进度条语义：上传阶段映射到 0–40%，上传完成置 45%，开始收到日志后置 90%，结束置 100%。

### 4.2 `core.py`

#### 4.2.1 网络辅助函数

| 函数 | 行为 |
|---|---|
| `local_ipv4()` | UDP 连接 `8.8.8.8:80` 取本机出口 IP（不实际发包） |
| `subnet_prefix(ip)` | 取前三段拼成 `x.y.z.` |
| `resolve_name(host)` | 反向 DNS 查主机名，失败返回空串（不阻塞流程） |
| `scan_ssh(prefix, on_found, stop_event, timeout=0.7, workers=128)` | 对 `/24` 的 1–254 并发 `create_connection(host, 22)`；成功读最多 128 字节 Banner 并反查主机名；支持停止事件 |

#### 4.2.2 `Box` 类

一台盒子 = 一个 `Box` 实例 = 一个 paramiko `SSHClient`。

| 成员 | 说明 |
|---|---|
| `OFFLINE_TGZ` | `/tmp/petpaint-offline.tgz` |
| `OFFLINE_DIR` | `/tmp/petpaint-offline` |
| `WIFI_JSON` | `/tmp/petpaint-wifi.json` |
| `LOG_PATH` | `/tmp/petpaint-provision.log` |

| 方法 | 设计要点 |
|---|---|
| `connect()` | `AutoAddPolicy`、`look_for_keys=False`、`allow_agent=False`；连接/认证/Banner 超时均 10s |
| `ensure()` | 惰性连接；transport 不活跃则关闭重连 |
| `_wrap_sudo(cmd)` | 非 root 用户统一包成 `sudo -n bash -c <quoted>`，`-n` 保证不弹密码提示 |
| `exec(cmd)` | 返回 `(exit_code, stdout, stderr)`，UTF-8 容错解码 |
| `check(cmd)` | exit code 非 0 抛 `BoxError` |
| `upload(local, remote, progress, chunk=262144)` | 256 KB 分块 SFTP 写，`set_pipelined(True)` 提升吞吐，回调 `(done,total)` |
| `write_text()/read_text()` | 小文件 SFTP 读写 |
| `system_info()` | 一次命令输出四行：`hostname`、`dpkg --print-architecture`、`PRETTY_NAME`、`findmnt -o SOURCE /` |
| `printer_present()` | `lpinfo -v \| grep -ciE 'selphy\|cp1500\|canon'` 计数 > 0 |
| `list_wifi()` | 纯 shell + nmcli，逐条输出 `连接名\tSSID\t优先级\t隐藏\t是否活动\tPSK`；`--` 视为空密码，`ssid` 为 `--` 的行丢弃 |
| `save_wifi()` | 连接名存在则 `nmcli connection modify`，否则 `nmcli connection add type wifi con-name ... ifname wlan0 ssid ...`；统一设置 `autoconnect yes`、优先级、隐藏；密码非空才写 `wifi-sec.key-mgmt wpa-psk`；成功以 `__SAVED_<conn>` 标记 |
| `delete_wifi()` | `nmcli connection delete` |
| `start_provision()` | 见 5.4 |
| `read_log()` | 读远端日志，文件不存在返回空串 |
| `wait_log()` | 每 1.5s 轮询，按增量回调 `on_chunk`，出现 `__EXIT__` 解析退出码，默认超时 1800s |
| `reboot()` | `sync; systemctl reboot`，异常吞掉（连接必然断） |
| `test_print()` | 远端用 Pillow 生成 1200×1800 彩色测试页 → `lp -d <queue>` |

WiFi 连接名生成规则：SSID 中凡不是 ASCII 字母/数字/`-`/`_` 的字符替换为 `-`，前缀 `petpaint-`，全空则用 `petpaint-wifi`。

## 5. 关键流程

### 5.1 设备发现

```
用户点「扫描设备」
  → local_ipv4() 取本机 IP（失败则提示检查网络）
  → subnet_prefix() 得 /24 前缀
  → 工作线程 scan_ssh(prefix, on_found)
       ThreadPoolExecutor(128) 并发探测 1..254，每个 0.7s 超时
       命中 → on_found(ip, banner, hostname) → after(0) 插入列表
  → 扫描结束保存名称缓存；若一条都没有，提示「确认盒子与电脑在同一路由器下」
```

扫描只判断 22 端口是否可连，不校验是否为盒子，因此列表里可能出现路由器、NAS 等设备；后续连接失败由用户自行忽略。

### 5.2 连接与信息读取

```
IP/用户名/密码 → Box(host,user,pass)
  → connect()（10s 超时）
  → system_info()：一次 SSH 命令取四行
  → printer_present()
  → _connect_ok()：展示信息、缓存主机名、异步 list_wifi()
  → 架构非 arm64 → 警告弹窗
```

「没接打印机」不算连接失败，只在信息区提示，第三步可勾「跳过打印机」。

### 5.3 WiFi 配置

- 读取：`nmcli -t -f NAME,TYPE connection show` 过滤 `802-11-wireless`，逐条查 SSID/PSK/优先级/隐藏，并以 `connection show --active` 判断活动连接。
- 写入（新增/修改）：构造一条带 `if ... then modify else add ... fi` 的 shell，避免先删后加导致的短暂断网；密码为空表示不修改密码。
- 删除：直接 `nmcli connection delete`。
- 每次写操作完成后统一重新读取列表，保证界面与服务端状态一致。

### 5.4 启动配置（核心）

```
Box.start_provision(tgz, wifi_rows, server, device_id, token, queue, skip_printer, progress)
  1. upload(tgz → /tmp/petpaint-offline.tgz)，256KB 分块，progress 回调
  2. write_text(/tmp/petpaint-wifi.json, JSON(wifi_rows))
  3. 拼参数：
       --server-url <server> --queue <queue> --wifi-json /tmp/petpaint-wifi.json
       [--device-id ...] [--device-token ...] [--skip-printer]
     每项 shlex.quote
  4. 远端执行：
       rm -rf /tmp/petpaint-offline
       && tar xzf /tmp/petpaint-offline.tgz -C /tmp
       && bash /tmp/petpaint-offline/provision.sh <args>
       ; echo __EXIT__$?
     外层用 setsid nohup bash -c '{ ... } > /tmp/petpaint-provision.log 2>&1' &
     立即返回 started
```

**为什么用 `setsid nohup`**：`provision.sh` 在最后阶段会切换 WiFi，SSH 连接可能断开；脱离会话后脚本仍会跑完，日志持续落盘，操作员恢复网络后重新连接即可继续查看。

### 5.5 日志轮询与完成判定

```
wait_log(timeout=1800, interval=1.5)
  offset = 0
  循环：
    读取全量日志 → 超过 offset 的部分回调 on_chunk 并推进 offset
    若文本含 __EXIT__ → 取最后一次标记后的数字作为退出码
    否则 sleep(1.5)
  超时 → BoxError("等待 provision.sh 超时")
```

退出码 0 → 界面提示「配置完成，拔网线、重启盒子，到后台确认设备在线」，并启用「重启盒子」「测试打印」。

### 5.6 重启与测试打印

- 重启：`systemctl reboot`，命令可能因连接中断返回异常，`Box.reboot()` 主动吞掉。
- 测试打印：远端 Pillow 画一张 1200×1800 彩条页（含 12px 黑边），保存 `/tmp/petpaint-test.jpg` 后 `lp -d cp1500` 提交；返回 `request id`。

## 6. 盒子侧 `provision.sh` 设计

脚本要求 root（非 root 自动 `exec sudo bash "$0" "$@"`），`set -euo pipefail`，可重复执行。运行用户按 `SUDO_USER` → `pi` → `root` 顺序推断。

| 步骤 | 内容 | 幂等/容错 |
|---|---|---|
| 1. 预检 | 校验 `arm64`、`nmcli` 存在，打印系统版本 | 不满足直接 `die` |
| 2. 修复 NM WiFi 插件 | 找 `libnm-device-plugin-wifi.so` 所在目录，属主非 `root:root` 则 `chown -R` 并重启 NetworkManager；`rfkill unblock wifi` | 属主正常则跳过 |
| 3. 本地 apt 源 | 写 `/etc/apt/sources.list.d/petpaint-offline.list`：`deb [trusted=yes] file:<offline>/debs ./`，用 `Dir::Etc::sourcelist` 隔离，安装 `cups cups-client cups-filters python3-pil`，启用 cups | 每次 update 幂等 |
| 4. Gutenprint | `lpinfo -m` 已有 cp1500 则跳过；否则 purge 系统旧版 `printer-driver-gutenprint`，`dpkg -i gutenprint/gutenprint-cp1500_*.deb`，`ldconfig`，重启 cups，再校验 PPD | 缺包 `die` |
| 5. USB 抢占 | 写 `blacklist usblp`、`modprobe -r usblp`、`stop/mask ipp-usb`，重启 cups | 失败不致命（`|| true`） |
| 6. CUPS 队列 | 优先选 `direct (usb\|gutenprint53+usb)://` 且含 `selphy/cp1500/canon` 的 URI，逐级回退；`lpadmin -p cp1500 -E -v URI -m PPD`，设 `PageSize=Postcard`、`StpBorderless=True`，`cupsenable`+`cupsaccept`；把运行用户加入 `lpadmin` 组 | 无打印机时：带 `--skip-printer` 跳过，否则 `die` |
| 7. WiFi | 解析 `--wifi-json`（`conn/ssid/password/priority/hidden`），逐条 delete→add→modify（autoconnect、priority、ipv4/ipv6 auto、psk、hidden）；连接优先级最高的一条，等待最多 30s 拿 IPv4；`curl --interface wlan0` 访问服务器校验连通性 | 无 `--wifi-json` 或 `--skip-wifi` 则跳过 |
| 8. print-agent | 复制 `agent.py`、`print_agent.py`、`config.json` 到 `/opt/petpaint/print-agent`；按运行用户与目录重写 systemd unit；有设备凭据时写 `agent.json`（server_url/device_id/device_token/printer_name/lp_options），`chmod 600`，`enable` + `restart`，3 秒后 `is-active` 校验 | 无凭据则只装不启动并告警 |
| 9. 汇总 | 输出 print-agent/cups 状态、`lpstat -r`、队列状态、wlan0 地址 | 仅展示 |

打印相关默认参数：队列 `cp1500`，`lp_options = ["-o","PageSize=Postcard","-o","StpBorderless=True","-o","print-scaling=none"]`。

## 7. 离线包设计

### 7.1 结构

```
petpaint-offline-5.3.6-YYYYMMDD-<buildid>.tgz
└── petpaint-offline/
    ├── provision.sh                       # 安装主脚本
    ├── debs/                              # 113 个 Debian 12 arm64/all 包（CUPS、Ghostscript、字体等）
    ├── gutenprint/
    │   └── gutenprint-cp1500_5.3.6_arm64.deb
    └── print-agent/
        ├── agent.py
        ├── print_agent.py
        ├── config.json
        └── print-agent.service
```

解包后约 126 个条目、45 MB 压缩体积。离线包的存在使整个流程**不需要盒子访问互联网下载依赖**，只有 WiFi 校验阶段需要能访问服务器。

### 7.2 更新机制

`tools/update-print-offline-bundle.py` 用于在不重打依赖的前提下更新脚本：

1. 打开现有 `.tgz`，逐条搬运；命中 `provision.sh` / `agent.py` / `print_agent.py` 时用仓库最新源码替换；
2. `.sh` 文件强制 LF（Windows 源码可能是 CRLF）；
3. 所有必需条目都替换到才写盘，否则报错并保持原包；
4. 写入临时文件后重新打开逐项校验字节一致；
5. `os.replace` 原子替换原包。

### 7.3 发布产物

| 文件 | 提交方式 |
|---|---|
| `provisioner/dist/PetpaintProvisioner.exe` | 普通 Git（约 16.9 MB） |
| `provisioner/dist/offline/petpaint-offline-*.tgz` | 普通 Git（约 43.7 MB） |

`provisioner/build.ps1` 会先删 `build/`、`dist/` 再重建，因此**重建后必须重新 `git add` EXE 与离线包**，否则其他电脑拉到的是旧版本。

## 8. 数据与格式

### 8.1 设备 CSV

`utf-8-sig` 编码，表头至少包含：

```csv
deviceId,token,label
dev_xxxxxxxx,tok_xxxxxxxx,1号店
```

- `deviceId` 为空的行忽略；
- `label` 仅用于下拉展示；
- token 在界面上只显示首尾各 8 位。

### 8.2 WiFi JSON（上传到盒子 `/tmp/petpaint-wifi.json`）

```json
[
  {
    "conn": "petpaint-store",
    "ssid": "店铺WiFi",
    "password": "xxxx",
    "priority": 300,
    "hidden": false,
    "active": true
  }
]
```

`provision.sh` 只使用 `conn/ssid/password/priority/hidden`，`active` 由界面读取时附带，脚本忽略。

### 8.3 `agent.json`（盒子 `/opt/petpaint/print-agent/agent.json`，权限 600）

```json
{
  "server_url": "https://www.petpaint.top",
  "device_id": "dev_xxxxxxxx",
  "device_token": "xxxxxxxx",
  "printer_name": "cp1500",
  "lp_options": ["-o", "PageSize=Postcard", "-o", "StpBorderless=True", "-o", "print-scaling=none"]
}
```

### 8.4 通信标记

| 标记 | 方向 | 含义 |
|---|---|---|
| `started` | 远端 → 本地 | 后台任务已拉起 |
| `__SAVED_<conn>` | 远端 → 本地 | WiFi 保存成功，带连接名 |
| `__EXIT__<code>` | 远端 → 本地 | provision.sh 结束及退出码 |

### 8.5 本地缓存

`%APPDATA%\PetpaintProvisioner\names.json`：`{"192.168.1.23": "petpaint-box-01"}`，用于扫描结果回显名称；损坏或不可写时静默降级为不缓存。

## 9. 异常处理与状态

| 场景 | 表现 | 处理 |
|---|---|---|
| 本机无 IP | 弹「没有获取到本机 IP」 | 中止扫描 |
| 扫描 0 结果 | 提示检查是否同一路由器 | 可改用直接填 IP |
| SSH 连接失败 | 信息区显示异常、弹窗 | 保留表单，可重试 |
| 架构非 arm64 | 警告弹窗，流程继续 | 用户可自行终止 |
| 未接打印机 | 信息区提示「未发现」 | 第三步勾选跳过 |
| 未选设备/token 缺失 | 警告弹窗 | 阻止开始 |
| WiFi 列表为空 | 警告并跳到第二步 | 至少配置一条 |
| 上传中网络中断 | 工作线程异常 → `_finish(1, msg)` | 日志提示重新连接后查看 `/tmp/petpaint-provision.log` |
| 脚本运行超时 | `wait_log` 抛 `BoxError` | 提示超时，日志仍在盒子 |
| WiFi 切换导致 SSH 断开 | `read_log()` 抛异常被吞、继续轮询 | 脚本靠 `setsid` 存活 |
| 测试打印失败 | 弹窗显示远端 stderr | 检查纸张、USB、队列 |
| 关闭窗口 | `_on_close` 置停止事件、关闭 SSH | 后台 daemon 线程随进程退出 |

## 10. 安全设计

| 项 | 设计 |
|---|---|
| SSH 密码 | 仅存在 `Box` 实例内存中，不落盘、不写日志、界面掩码 |
| 主机指纹 | `AutoAddPolicy`（现场设备多、IP 复用，不做严格校验，属于已知取舍） |
| sudo | `sudo -n`，要求盒子已配置免密 sudo（Armbian 默认 root 或 pi 免密） |
| 设备 token | 只写入盒子 `agent.json`，`chmod 600`、属主为运行用户；本地 CSV 由操作员保管 |
| 本地 apt 源 | `[trusted=yes]` 仅指向离线包目录，安装源可追溯 |
| 日志 | 远端 `/tmp/petpaint-provision.log` 不包含密码/token |
| 打包 | `--windowed`，不弹控制台，避免误触命令行 |

## 11. 性能设计

| 环节 | 设计 | 量级 |
|---|---|---|
| 扫描 | 128 并发、0.7s 超时 | /24 全网段约 5–10s |
| 反向 DNS | 每次探测成功后立即解析，失败即空 | 不阻塞整体 |
| 上传 | 256 KB 分块 + SFTP pipelined | 45 MB 一般 10–40s（取决于 Wi-Fi/百兆） |
| 日志 | 1.5s 轮询增量 | 近实时，开销可忽略 |
| 界面 | 全部网络操作在后台线程 | 不冻结 tkinter |

## 12. 构建与发布

### 12.1 构建步骤（`build.ps1`）

```powershell
./build.ps1 -Python python
```

1. `pip install --upgrade pyinstaller paramiko`；
2. 删除 `build/`、`dist/`；
3. `PyInstaller --onefile --windowed --name PetpaintProvisioner --collect-submodules paramiko main.py`；
4. 找离线包源目录：`provisioner/offline` 优先，否则 `../print-agent/offline`；
5. 调 `tools/update-print-offline-bundle.py --directory <源>` 用最新脚本刷新包内文件；
6. 复制 `petpaint-offline-*.tgz` 到 `dist/offline/`。

### 12.2 交付目录

```
provisioner/dist/
├── PetpaintProvisioner.exe
└── offline/
    └── petpaint-offline-5.3.6-20261121-073bbb76.tgz
```

EXE 与 `offline/` 必须放在一起分发；`find_offline_package()` 也支持回退到仓库的 `print-agent/offline`。

### 12.3 版本管理

- `.gitignore` 只忽略 `build/`、`*.spec`、`__pycache__/`、`provisioner/offline/`；`dist/` 下 EXE 与离线包入库。
- 根 `.gitignore` 中 `dist` 已改为 `/dist`，仅忽略仓库根目录的 `dist`，不影响子目录。
- 离线包文件名含日期与 build id（`5.3.6-20261121-073bbb76`），便于追溯是哪个构建。

## 13. 运维排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 扫描不到盒子 | 不同网段/防火墙/盒子未开机 | 确认同一路由器；直接填 IP |
| 连接超时 | SSH 未启用、IP 错误 | 检查盒子 SSH 服务 |
| `sudo: a password is required` | 用户无免密 sudo | 用 `root` 登录，或配置 NOPASSWD |
| 架构报错 | 系统为 armhf/amd64 | 重刷 64 位镜像 |
| apt 失败 | 离线包缺 deb、磁盘空间不足 | `df -h`，校验包完整性 |
| 找不到 CP1500 PPD | Gutenprint 未装上/旧版冲突 | 重新执行脚本，看第 4 步输出 |
| 队列建不起来 | USB 未识别、被 usblp/ipp-usb 抢占 | 确认第 5 步黑名单生效，重插 USB |
| WiFi 写入后断连 | 切换网络导致 SSH 断开 | 用网线，恢复后重连看日志 |
| WiFi 连上但不能上网 | 密码错/路由器限制 | 看 `curl --interface wlan0` 结果 |
| print-agent 未启动 | agent.json 凭据错误、服务异常 | `journalctl -u print-agent -n 50` |
| 测试打印不出纸 | 缺纸、托盘满、队列暂停 | `lpstat -p cp1500`、`cupsenable cp1500` |

远端日志位置：`/tmp/petpaint-provision.log`。

## 14. 已知限制与后续演进

**已知限制**

- 仅支持 arm64（armhf 盒子无法使用当前离线包）。
- 扫描仅判断 22 端口开放，无法区分盒子与其他 Linux 设备。
- 一次只能配置一台盒子（串行作业），没有批量队列。
- SSH 主机指纹不校验。
- 离线包与 EXE 需同目录分发；重建后需手动提交新二进制。

**可演进方向**

- 批量模式：扫描结果多选，串行执行并汇总结果。
- 配置模板：把「服务器 + 队列 + WiFi 列表 + 跳过打印机」保存为现场模板。
- 离线包按需裁剪（只带 CUPS 依赖）以减小体积。
- 增加「配置完成后自动心跳校验」，直接查后台设备在线状态。
- 增加代码签名，降低 Windows SmartScreen 拦截。
